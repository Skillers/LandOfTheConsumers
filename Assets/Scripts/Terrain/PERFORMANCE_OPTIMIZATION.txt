TERRAIN GENERATION PERFORMANCE OPTIMIZATION
============================================

WHAT WAS CHANGED:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The terrain generation code has been optimized based on your suggestion!
Previously, terrain noise was calculated for EVERY voxel position.
Now, it's calculated ONCE per vertical column and stops early when only air remains.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

BEFORE (OLD CODE):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

for x in chunk:
    for y in chunk:
        for z in chunk:
            worldPos = calculate position (x, y, z)
            noise = GetTerrainNoise(worldPos.x, worldPos.z)  ← SLOW! Called 17×17×17 = 4,913 times per chunk
            terrainHeight = calculate height
            density = terrainHeight - worldPos.y
            voxels[x,y,z] = density

Problems:
• Noise calculated 4,913 times per chunk
• 90% of voxels are air (above terrain) but still processed
• Y component doesn't affect noise, but we loop through it anyway
• Wastes CPU on calculations we already know the result of

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AFTER (NEW CODE):
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

for x in chunk:
    for z in chunk:
        worldX = calculate X position
        worldZ = calculate Z position

        noise = GetTerrainNoise(worldX, worldZ)  ← FAST! Called only 17×17 = 289 times per chunk
        terrainHeight = calculate height

        maxY = ceiling(terrainHeight) + 2  ← Stop processing above this

        for y from 0 to maxY:  ← Only process voxels near/below terrain!
            density = terrainHeight - worldY
            voxels[x,y,z] = density

        for y from maxY+1 to chunk.height:  ← Simple fill for air above
            voxels[x,y,z] = (negative air value)

Benefits:
• Noise calculated only 289 times per chunk (17× fewer!)
• Y loop exits early when terrain surface is reached
• High altitude chunks (mostly air) generate almost instantly
• No wasted calculations on voxels we know are air

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

WHY THIS WORKS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Your terrain uses 2D noise (only X and Z coordinates):

    noise = GetTerrainNoise(x, z, 0)  ← Y is always 0!
                                 ↑
                               ignored

This means:
• Terrain height only depends on X,Z position
• Once we know the height for a column, ALL voxels in that column
  either below surface (solid) or above surface (air)
• We don't need to recalculate noise for every Y value!

Example column at X=5, Z=10:

    Old way:                    New way:
    ────────────────────────    ────────────────────────
    Y=16: Calculate noise ✗     Y=16: Skip (air)
    Y=15: Calculate noise ✗     Y=15: Skip (air)
    Y=14: Calculate noise ✗     Y=14: Skip (air)
    Y=13: Calculate noise ✗     Y=13: Skip (air)
    Y=12: Calculate noise ✗     Y=12: Skip (air)
    Y=11: Calculate noise ✗     Y=11: Skip (air)
    Y=10: Calculate noise ✓     Y=10: Use cached height
    Y=9:  Calculate noise ✓     Y=9:  Use cached height
    Y=8:  Calculate noise ✓ ←── Y=8:  Use cached height ← Calculate ONCE here!
    Y=7:  Calculate noise ✓     Y=7:  Use cached height
    Y=6:  Calculate noise ✓     Y=6:  Use cached height
    Y=5:  Calculate noise ✓     Y=5:  Use cached height
    Y=4:  Calculate noise ✓     Y=4:  Use cached height
    ...                         ...

    Terrain surface at Y=8     Terrain surface at Y=8
    17 calculations            1 calculation + simple fills

TECHNICAL DETAILS:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The optimization works by:

1. Reordering loops from X→Y→Z to X→Z→Y
   • This groups processing by vertical columns
   • Allows us to calculate terrain height once per column

2. Early exit calculation
   • maxY = ceil(terrainHeight / voxelSize) + 2
   • The +2 margin ensures marching cubes has enough data for interpolation
   • Any Y above maxY is guaranteed to be air

3. Two-phase fill
   • Phase 1: Fill voxels from Y=0 to Y=maxY (near/below surface)
   • Phase 2: Simple fill voxels from Y=maxY+1 to Y=max (air above)

4. Memory access pattern
   • New pattern is more cache-friendly (processes columns sequentially)
   • Reduces cache misses when accessing noise lookup tables

Potential further improvements:

1. Skip empty chunks entirely
   • If entire chunk is above terrain, don't generate mesh at all
   • Saves memory and rendering cost

2. Chunk pooling
   • Reuse mesh objects instead of creating/destroying
   • Reduces garbage collection pauses

3. Multi-threaded generation
   • Generate multiple chunks in parallel
   • Modern CPUs have 4-16 cores waiting to help!

4. GPU compute shaders
   • Offload voxel generation to GPU
   • Could be 10-100× faster for large worlds

5. Level of Detail (LOD)
   • Distant chunks use lower resolution
   • Massive performance gain for large view distances
